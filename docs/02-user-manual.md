# QiYun-LapTimer-Node 操作手册

> 面向 DIY 用户与赛场操作员的完整操作流程。按章节顺序执行即可从零到开赛。
> 适用固件 `1.0.9` / 文件系统 `1.0.7`

---

## 0. 快速上手路线

```
① 采购与 SPI 改造 ──▶ ② 接线 ──▶ ③ 编译烧录（固件 + 文件系统，两步）
        ──▶ ④ 连热点打开 33.0.0.1 ──▶ ⑤ 配置页设频段/机型 ──▶ ⑥ 校准向导
        ──▶ ⑦ 比赛页开飞 ──▶（可选 ⑧ 配飞手 ID + API 地址上云）
```

最快检查点：上电后应听到**一长亮 + 短叫**（LED 亮 400 ms、蜂鸣 200 ms），手机能搜到 `QYLPT_XXXX` 热点并打开页面——看到首页即说明硬件和烧录全部正确。

## 1. 物料准备

### 必需

| 物料 | 要求 | 参考价 |
|---|---|---|
| ESP32 开发板 ×1 | 带 USB 任意型号；开箱支持 `esp32dev`（WROOM/WROVER）、`esp32doit-devkit-v1`、`esp32-c3-devkitm-1`、`esp32-s3-devkitc-1` | ¥15–35 |

> 💰 整机预算约 **¥250–270 起**（不含供电与蜂鸣器；外壳用仓库模型自打，只算几十克耗材），RX5808 是主要成本项。建议先做一台验证场地效果。

### 可选但强烈推荐

| LED + 限流电阻 | 任意颜色，串 220Ω–1kΩ（多数开发板有板载 LED 可直用） | 状态指示 |
| 电压监测 | 外接 **1/2 分压**（两个等值电阻）到 VBAT 引脚 | 1S 锂电低压告警 |
| 计时门 | 直径 1 m（2 寸机）或 2 m（5 寸机） | 与软件"飞机大小"设置对应 |
| 外壳 | **模型已随仓库提供**：底座 + 上盖两半，内腔约 29 × 61 mm，装 ESP32 + RX5808 整机 | 户外防风防尘、固定走线；打印参数见 [3d/README.md](3d/README.md) |

### 外壳 3D 打印（可选）

`docs/3d/` 下有 `enclosure-bambu-studio.3mf`（Bambu Studio 工程，拖进去即得完整设置）与两个 `case-*.stl`。成型要点：PETG、层高 0.2 mm、壁 4 圈、填充 35 % gyroid、树状支撑、无 brim/raft；合盖总高 26.5 mm。文件清单、逐条参数、换材料注意事项与验收步骤见 [外壳 3D 模型与打印参数](3d/README.md)。不方便下载仓库的话，也可从线上发布页取压缩包：<https://www.crealitycloud.cn/model-detail/6ad9d953328846f6477a79e6>。

## 2. 接线

⚠️ **RX5808 的 `+5V` 引脚请接 ESP32 的 `3V3`**——故意欠压供电，可提高 RSSI 分辨率并降低模块发热。这是正常工作的前提，不是接线错误。

按手上的板子选列（`ESP32` 列对应经典 WROOM/WROVER/DOIT）：

| 接到 RX5808 / 外设 | ESP32 | ESP32-C3 | ESP32-S2 | ESP32-S3 |
|---|:---:|:---:|:---:|:---:|
| RSSI | **33** | 3 | 3 | 13 |
| CH1 (DATA) | **19** | 6 | 6 | 11 |
| CH2 (SEL) | **22** | 7 | 7 | 10 |
| CH3 (CLK) | **23** | 4 | 4 | 12 |
| +5V → 接 3V3 | **3V3** | 3V3 | 3V3 | 3V3 |
| GND | **GND** | GND | GND | GND |
| 蜂鸣器 (+) | **27** | 5 | 5 | 3 |
| LED | **2**（板载） | 8（板载） | 13（板载） | 48（板载） |
| VBAT 分压中点 | **35** | 0 | 4 | 1 |

经典 ESP32 接线示意：

![ESP32 与 RX5808 接线示意图](assets/wiring-esp32.png)

> 图中 LED 画在 GPIO21，属早期方案接法；当前固件经典 ESP32 的 LED 使用**板载 GPIO2**，无需外接（若外接请串 220Ω–1kΩ 电阻并改接 GPIO2）。蜂鸣器、LED 负极均接 GND。

**注意事项**

- RSSI 必须接 ADC1 引脚：经典 ESP32 只有 GPIO32–39 支持模拟输入（用 33）；GPIO25/26 属 ADC2 与 WiFi 共用不可用；GPIO34/35/36/39 只能输入不能输出。
- **ESP32-S2**：`config.h` 有引脚表，但 `platformio.ini` 没有对应构建环境，需自行加一个 `[env:...]`。
- 引脚定义唯一来源是 `lib/config.h:28` 起的 `#define`（同文件顶部注释为接线表，已与之对齐）。

## 3. 固件烧录

### 3.1 环境搭建

| 步骤 | 操作 |
|---|---|
| 1 | 安装 [VS Code](https://code.visualstudio.com/) |
| 2 | 扩展面板搜 `platformio`，安装 **PlatformIO IDE** |
| 3 | 安装 git，`git clone https://github.com/onebody/QiYun-LapTimer-Node.git` 并用 VS Code 打开 |
| 4 | 首次构建自动下载 espressif32@6.9.0 与四个依赖库，**耗时几分钟且需要联网**，别中断 |

### 3.2 编译与烧录（两条命令，缺一不可）

以 `esp32dev` 环境为例。**先烧固件，再烧文件系统**——只烧固件设备能跑但没有网页。

```bash
# ① 编译并烧录固件
pio run -e esp32dev -t upload --upload-port /dev/cu.SLAB_USBtoUART   # macOS
pio run -e esp32dev -t upload --upload-port COM5                      # Windows
pio run -e esp32dev -t upload --upload-port /dev/ttyUSB0              # Linux

# ② 编译并烧录文件系统（网页界面）
pio run -e esp32dev -t uploadfs --upload-port /dev/cu.SLAB_USBtoUART
```

图形界面路径：VS Code 左侧 PlatformIO 图标 → `PROJECT TASKS` → `General: Build` / `Upload`，再展开 `Platform: Upload Filesystem Image`。

> `data/` 目录就是文件系统镜像的全部内容。只改网页（`index.html` / `script.js` / `style.css`）时重跑 ② 即可，不用重烧固件。

### 3.3 容量红线

app 分区各 1.25 MB，全功能构建约 954 KB（73%）。**加较大的新功能前先看编译末尾的 Flash 百分比**。

## 4. 首次连接

1. 上电，确认 LED/蜂鸣开机提示。
2. 手机连 WiFi：热点 **`QYLPT_XXXX`**（`XXXX` 是 MAC 去冒号后的末 4 位十六进制，上电后串口日志会打印完整热点名），密码 **`12345678`**。
3. 一般会自动弹出配置页；没弹出就手动打开 **`http://33.0.0.1`** 或 `http://qylpt.local`。
4. iOS 需在「设置 → WiFi」里点"取消"捕获页后再打开浏览器。

**如果 RSSI 曲线一直是 0 或满格**：先查 RX5808 的 SPI 改造和 `+5V→3V3` 这条线。

### 接入赛场路由器（STA 模式）

进「配置」页填 WiFi 名称 + 密码 → 点「保存配置」→ 设备重启后用新 IP 访问。

- 只支持 **2.4 GHz**；5 GHz 单独 SSID 连不上。
- **只有 WiFi 名或密码变化时，保存才会触发重启**；其余参数保存即时生效。
- 连续 3 次连接失败会自动降级回 AP 模式（蜂鸣 1 s 提示）。

## 6. 配置页参数详解

| 界面项 | 范围 | 实际存储 | 作用 |
|---|---|---|---|
| 频段 / 频道 | A B E F R L × 1–8 | `frequency`（MHz，uint16） | RX5808 调谐目标。**必须与飞机 VTx 一致** |
| 当前频率 | 只读 | — | 由频段+频道查表得出 |
| 最小圈时 | 1–10 s，步进 0.5 | `minLap = 秒 × 10` | 防重复计数闸门（固件再 ×100 → ms） |
| 低电压告警 | 2.6–3.6 V，步进 0.1 | `alarm = 伏 × 10` | 低于此值蜂鸣+闪灯；**存 0 表示关闭** |
| 播报类型 | 关闭 / 蜂鸣 / 单圈用时 / 累计用时 | `announcerType` 0–3 | 浏览器 TTS 内容 |
| 播报速率 | 0.1–2.0 | `announcerRate = 倍率 × 10` | 语速 |

## 7. 校准（最关键的一步）

校准确定"多强的信号算过门"。做不好会漏圈或多圈。

### 准备工作

- 计时器放在计划位置（门柱旁/门中央地上，离地约 20–50 cm 的一致高度）。
- 飞机通电、按**实际比赛功率**发射，**等 30 秒让 VTx 达到工作温度**。

### 三步向导

先在向导上方的「飞机配置与校准」区选好**飞机大小**（2 寸 → 计时门 1.0 m；5 寸 → 2.0 m，页面会同步显示门径）。此选择决定门径与固件判圈用的变化量（2 寸 ≥10、5 寸 ≥6，与下面「要求 ≥35 / ≥19」不是一回事，见后文提示），**选错会直接导致漏判**。然后走向导三步：

1. **开始校准**：页面显示当前频段/频道/频率与机型门径，确认后点「开始校准」，固件开始累加采样。
2. **校准进行中**：飞机放在**起飞点**（离门一个门径以上）、**不要移动**；固件累加采样并取最大 RSSI 作为底噪，面板实时显示 RSSI 值、进度（采样数 / 目标数，目标数 = 高级设置里的「采样次数」，10–200，默认 20；现场信号越吵建议调大）与实时推荐进入/退出阈值。够数后点「停止校准」。
3. **确认并应用**：显示底噪、峰值、信号强度差（附「要求 ≥」参考值）与推荐配置，滑块已自动就位。可手动微调，然后点「应用并保存」写入；点「取消」则放弃本次结果。

### 判断校准是否可靠

看第 3 步的「信号强度差（要求 ≥ X）」：**要求值由门径决定——2 寸机 ≥ 35、5 寸机 ≥ 19**（`data/script.js:222`）。差值低于要求值说明飞机离门太远或 VTx 功率太低，此时推荐阈值不可靠，应先解决摆放位置与发射功率，而不是硬用。

> ⚠️ 别把它和**固件**判圈用的变化量混为一谈：`lib/laptimer.cpp:167` 里 1.0 m 门用 10、2.0 m 门用 6，那是过圈时"峰值要回落多少才算完成一圈"的实际门槛；页面上的 35 / 19 只是**校准阶段**评估信号余量的参考值。

### 微调方向

推荐值以「RSSI 降低量(百分比)」（默认 30 %，范围 10–100）为旋钮，算法在 `data/script.js:201` `getCalibrationTuning()`：

- `进入比例 = clamp(1 − 百分比 × 0.7)` 再按门径校正、最终夹在 **0.65–0.9** → **百分比越大，进入阈值越低，越容易判过门（越灵敏）**；
- `退出比例 = clamp(1 − 百分比 × 1.3)`，夹在 0.3–0.8，同理；
- 门径越小，校正后的进入比例越高（要求信号更强）。

- **默认 30 % 适合大多数场景**。
- **漏圈** → 把百分比调**大**（进入阈值下调），或直接手动下调进入阈值。
- **多圈 / 炸机后乱跳** → 把百分比调**小**，并配合提高「最小圈时」。

### 手动兜底法（向导不可用时）

1. 飞机停在起飞点，读曲线底噪值 N；
2. 手持飞机快速走过计时门正下方，读峰值 P；
3. `进入阈值 ≈ N + (P − N) × 0.7`，微调直到"只有过门才触发"。

### 多机同场

邻道 VTx 会抬高底噪：把进入阈值整体上调几个点，并用「高级设置 → 采样次数」加大采集量。

## 8. 比赛流程

1. 「比赛」页签点 **开始** —— 蜂鸣 + 亮灯，固件进入计时状态。
2. 过圈时圈速表逐行增加（SSE 实时推送），按播报类型发声。
3. 点 **停止** —— 结束计时；**若配好飞手 ID 且已联网，此刻自动上传训练数据**。
4. 点 **清空** 重置表格。

> ℹ️ **第一行是"开圈"，没有成绩，属正常。** 按下开始后的第一次过门只用来对齐相位，从第二次过门起才是第 1 圈。**习惯：按下开始后正常飞一圈别管它，之后的成绩都准。**

累计用时与圈速表**只存在浏览器里，刷新页面即清空**——重要场次请先配好上云，以云端记录为准。

## 9. 训练数据上云

1. 「配置」页填写 **飞手 ID**（必填，空则不上传）与 **API 地址**（你自己的平台地址，不要留默认内网示例）。
2. 设备必须处于 **STA 已联网** 状态。
3. 停止计时即自动 `POST <API地址>/training/device_upload`。
4. 服务端响应体需包含 `{"success": true}` 才算成功。
5. 反馈：**成功蜂鸣 200 ms；失败蜂鸣 1 s + 闪灯**。

时间戳依赖设备 NTP（东八区硬编码、开机时同步）。无外网或海外场地时时间可能回到 1970 或偏差——此时不要用上传的数据做计时依据。

| 固件 | 固件更新 | `.pio/build/<env>/firmware.bin` | 上传成功后自动重启 |

## 12. 故障排除速查

| 现象 | 排查顺序 |
|---|---|
| 找不到 `QYLPT_XXXX` 热点 | ① 板子电源 LED 是否亮 ② 是否烧过 `uploadfs` ③ 换 USB 线/口（部分线只能充电） |
| 页面空白 / index.html missing | 没烧文件系统镜像，重跑 `pio run -e <env> -t uploadfs` |
| 连上 WiFi 打不开页面 | 直接输 `http://33.0.0.1`；iOS 先"取消"捕获页再开浏览器 |
| STA 连不上家里路由 | ① 仅支持 2.4 GHz ② 密码含特殊字符先试纯字母 ③ 3 次失败自动降级回 AP（蜂鸣 1 s） |
| RSSI 曲线恒 0 | SPI 改造没做 / CH1-3 接错 / RSSI 线没接；确认频段频道与飞机一致 |
| RSSI 顶满不动 | `+5V` 误接 5V（应接 3V3）；或 RSSI 接了非 ADC1 引脚 |
| 漏圈 | 重新校准；进入阈值调低；「采样次数」加大；确认机型选对（2 寸门要求变化量 ≥10） |
| 多圈 / 炸机后乱跳 | 提高「最小圈时」到略小于真实最快圈速；进入阈值调高；计时器移出赛道内侧改放门柱旁 |
| 第一圈没有成绩显示"开圈" | **正常行为**，见第 8 节 |
| 没有语音 | ① 必须先点「开启语音」 ② 播报类型不能是"关闭"（注意 localStorage 覆盖） ③ 系统需装对应语言语音包 |
| 云端没数据 | 飞手 ID 是否为空、是否 STA、API 地址是否改成自己服务器、响应需含 `{"success": true}`；失败有 1 s 蜂鸣 |
| 时间戳 1970 / 差 8 小时 | NTP 未同步成功（无外网）或不在东八区，见第 9 节 |
| 电压告警不准 | 分压比与 `VBAT_SCALE`/`VBAT_ADD` 不符；经典 ESP32 VBAT 用 GPIO35 |

## 13. 安全与合规须知

- 更新与配置接口**无鉴权**：只在可信网络使用，禁止接入公共 WiFi 或端口映射。
- `GET /config` 会明文回显 WiFi 密码。
- 5.8 GHz 图传功率请遵守当地法规与赛场规定。
- 长期赛场部署前，建议自行加接口鉴权（见《开发指南》已知限制 #1 的修复建议）。
